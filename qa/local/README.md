# IPDAMS local Docker + Playwright starter (synthetic-only)

**Status: prepared and statically validated; Docker/Chromium execution NOT TESTED in the authoring environment.**

## Scope and safeguards

- Applies ONLY to the owner-approved local checkout of private `ronilocanedo/ipdams`, branch `develop/hostinger-v0.2.375` or an authorized local feature branch. Never install these files on Hostinger.
- Docker `web` is built from local *allowlisted source files* (NOT a live Hostinger export) and bound on **127.0.0.1:8877** only. The MariaDB has **no published port**. Both run on a Docker `internal` network. No production credentials are copied to the image.
- `qa/local/Dockerfile.dockerignore` deliberately excludes `.env`, operational data, backups, Git, and other unapproved files from the web image build context. The site is baked into the image; after source edits rerun `start.ps1` to rebuild.
- QA container state is stored in named Docker volumes `qa_db`, `qa_storage`, and `qa_uploads`. **Do not run `docker compose down -v` unless you deliberately intend to delete only the synthetic QA volumes.**
- `APP_ENV=test`, database name `ipdams_qa`, synthetic credentials randomly generated by `init.ps1`. Do not copy Hostinger `.env`, SQL dumps, emails, identity documents or actual school financial records to local QA.
- Existing owner-local uncommitted review files and disabled reference `.spec.cjs.txt` files are not overwritten. These new Playwright tests are active `.spec.cjs` files.
- Nothing here creates a release, migrates production, automates GitHub Actions, or sends source changes to GitHub/Hostinger.

## First run on Windows, after Docker Desktop is installed and running

Open **PowerShell in the IPDAMS repository root**, then run:

```powershell
.\qa\local\init.ps1
.\qa\local\start.ps1
```

Use `http://127.0.0.1:8877` in your browser. The initial empty database is built from the **historical** `001_initial.sql` and `002_manual_signature_records.sql` migrations. These are not a complete current production schema. To validate the limitation:

```powershell
docker compose --env-file qa/local/.env.qa -f qa/local/compose.yaml exec -T web php /opt/ipdams-qa/check_schema.php
```

A `BLOCKED` result is expected if newer columns/tables are missing. **Do not run authenticated procurement, reimbursement, DV, posting or settlement tests until the current schema has been independently reconstructed from approved source/migrations and populated with synthetic-only fixtures.** We will handle that as a separate reviewed QA milestone.

## Run browser smoke tests

```powershell
docker compose --env-file qa/local/.env.qa -f qa/local/compose.yaml --profile qa run --rm --build playwright
```

This runs **only** `anonymous-smoke.spec.cjs` on Chromium desktop and mobile against Docker `http://web`: anonymous session, rendered login shell, JavaScript errors, console/network errors, horizontal overflow and screenshots. The fixture-dependent `pr-uacs-v0380.spec.cjs` remains excluded from the default run and requires its separate `pr-uacs-v0380.config.cjs`, a reviewed synthetic schema, approved test accounts and dedicated isolation variables. They do not represent full application/finance acceptance. Reports are saved to `qa/playwright/playwright-report` and `qa/playwright/test-results` (ignored by Git).

## PHP checks (safe, no financial writes)

```powershell
docker compose --env-file qa/local/.env.qa -f qa/local/compose.yaml exec -T web php -l private/app/bootstrap.php
docker compose --env-file qa/local/.env.qa -f qa/local/compose.yaml exec -T web php private/tests/unit.php
docker compose --env-file qa/local/.env.qa -f qa/local/compose.yaml exec -T web php private/tests/settings_smoke.php
```

**Do not execute `private/tests/integration.php` yet.** It writes synthetic financial records and needs a carefully reviewed current schema plus isolated disposable fixtures.

## Stop without deleting test data

```powershell
docker compose --env-file qa/local/.env.qa -f qa/local/compose.yaml down
```

If port 8877 is in use, change `QA_HTTP_PORT` in ignored `qa/local/.env.qa` before starting. The Playwright runner connects internally to `http://web` and does not use that host port.

## Known gaps / gate status

- Baseline source includes React 16, retained only for compatibility; no frontend rewrite was attempted.
- PHP 8.2 + MariaDB 10.11 are selected from the project's documented runtime compatibility assumptions, but have not been executed here.
- Historical migration 001 omits newer runtime schema fields (for example `organizations.address`), so full authenticated workflows are **BLOCKED** pending source-based schema reconciliation.
- First-time setup at `/setup.php` requires the randomly generated `QA_SETUP_TOKEN` in the ignored `.env.qa` and a writable private storage volume. Never reuse credentials outside local QA. Do not create live accounts in QA.
- The Playwright package is version-pinned to `1.64.1` to match the Microsoft Docker image. Its dependency installation occurs when Docker builds the *local Playwright test image*. This does not install anything to Hostinger.
- Docker images and npm packages will need to be downloaded on first local startup. No automatic CI, push, migration to production, or release was configured.
- Last checkpoint: SHA-256 matches for Hostinger `app.html`, property CSS and branding fallback vs saved QA candidates; complete source parity is not yet established.

**Next QA milestone:** validate the stack boot + browser smoke; then build a reviewed up-to-date synthetic schema and fixture pack before role-based and financial tests.

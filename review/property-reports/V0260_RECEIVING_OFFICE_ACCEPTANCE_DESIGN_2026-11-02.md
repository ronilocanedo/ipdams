# IPDAMS v0.2.260 — Receiving-office acceptance design

**Current installed build: v0.2.259. No acceptance write action is implemented.** Division users can open Property Accountability → Custody & Returns → Incoming Transfers, but the screen is intentionally read-only. The owner's test transfer is correctly pending; no asset should be duplicated or moved manually.

**Required implementation:** (1) bind the existing formally appointed Division Property Custodian to a specific authenticated, Division-scoped account; a signatory name alone is not an authorization grant; (2) add per-property physical inspection, condition, receipt date, storage location and signed-document reference; (3) accept only a pending registered-destination transfer addressed exactly to that office; (4) atomically close source custody, retain original source asset and finalized ICS/PAR records, create or activate a *linked* destination register entry with original IAR/property provenance, append receiver/source audit and finalize receipt; (5) enforce duplicate tag/serial, receiving catalog mapping, lifecycle, concurrency, scope and no-disposal restrictions; (6) do not reactivate `OUTSIDE IPDAMS` documentary destinations or falsely claim manual signatures are electronic approvals.

**Key verified blockers:** `PropertyTransferWorkflow::incomingForDivision()` is read-only; `public/api/property-transfers.php` has POST `prepare`, `record_pending`, `cancel` only. `ORG_SUPPLY_PROPERTY_CUSTODIAN_V1` stores employee appointment for IAR signatory, not authenticated user authorization. The original `assets.item_id` and `iar_line_id` reference source organization historical inventory/procurement records and must not be broken by a naive `assets.organization_id` update.

**Release gate:** real MariaDB transaction/locking and authenticated cross-organization UAT, duplicate rejection, atomic rollback, audit, signed reference, receiving and sending registers/report consistency, no duplicate acquisition accounting, and a v0.2.259 source-integrity updater. **This commit is a design checkpoint only; no v0.2.260 installer has been prepared or deployed.**

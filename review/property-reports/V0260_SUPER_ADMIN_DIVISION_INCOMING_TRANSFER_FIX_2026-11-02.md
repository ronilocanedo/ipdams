# IPDAMS v0.2.260 — Division Incoming Transfers Super Admin workspace fix

Owner installed v0.2.259 and selected an active Division workspace while signed in as SUPER_ADMIN. The Transfer tab errored with `Select an active organization in your workspace`. Root cause: the PHP transfer endpoint and React tab wrongly inferred school-only transfer context from SUPER_ADMIN role, ignoring the selected organization kind.

The new **v0.2.260** version-gated ZIP fixes organization-kind validation and dispatch: Super Admin in Division sees the read-only Incoming Transfers inbox and Division-scoped transfer printouts, while Super Admin in a school sees the normal Property Transfers desk. Division/school roles cannot impersonate the other organization kind. Incoming Division POSTs are explicitly forbidden, and printing a transfer from a different Division is refused. The frontend tab label follows the selected workspace. No receiving acceptance, cross-organization asset movement, additional role grant, financial change, database migration or number reset is implemented.

# IPDAMS v0.2.269 — current ICS/PAR versus historical accountability

## Owner observation and root cause
Owner reports on installed v0.2.268 that Division Consolidation → ICS/PAR lists the source-school October ICS and the receiving-Division November ICS for property tag `306351-2610-0004` as two finalized records. This is **not duplicate recording of the current asset**: both documents are immutable historical evidence, but only one should be counted in *current accountability*.

The transfer acceptance workflow writes a `document_links` closure from the source `ICS`/`PAR` document to the accepted `ITR`/`PTR`. The sender asset changes to `TRANSFERRED`; the receiving asset is registered `ACTIVE`. The receiving office may issue a new ICS/PAR. The original `accountability_documents.status` remains `FINALIZED`, by design. Formal return closures use `RRSP`/`PRR`.

## Exact change
- `ICS_PAR` is now **Current ICS / PAR**. It lists only the **latest FINALIZED** accountability document per asset within its organization, only when the owning asset status is `ACTIVE` and no `RRSP`, `PRR`, `ITR` or `PTR` closure link exists.
- New `ICS_PAR_HISTORY` is **ICS / PAR History**. It preserves every other original document in its original office, with an explanation: CLOSED BY TRANSFER, CLOSED BY RETURN, NOT FINALIZED, ASSET NOT ACTIVE, or SUPERSEDED.
- Both reports use the existing office scope and grants. The original `school_id` filter remains server-side validated; grants are not broadened.
- Overview counts use the exact same open/closed SQL predicate as the detail registers.
- Current ICS/PAR is **not** filtered by issuance month; History *is* date-filterable. All source document dates and numbers remain untouched.
- No update to `assets`, `accountability_documents`, `document_links`, custody records, transfers, accounting, authorizations, or SQL schema.

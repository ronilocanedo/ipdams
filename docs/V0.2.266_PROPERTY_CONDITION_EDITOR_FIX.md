# IPDAMS v0.2.266 — Property condition editor white-screen fix

**Version gate:** installed v0.2.265 -> v0.2.266. **No migrations.**
**Source:** exact installed v0.2.265 `assets/app.js` verified through read-only Hostinger source inspection before editing.

**Cause:** the React 16.0.0 property editing dialog referenced `e.target.value` inside a deferred functional `setState` callback. React 16 pools SyntheticEvent objects and may clear `e.target` before deferred work. Changing a condition such as *For Repair* -> *Serviceable* could throw `Cannot read properties of null (reading 'value')`, unmounting the editor/SPA.

**Narrow fix:** six onChange handler definitions capture `const value=e.target.value` *during the event* and pass the primitive value to functional `setState`. Existing updater logic and permission guards are unchanged. The browser cache key in `app.html` is bumped to ensure the script reloads. Only `public/assets/app.js` and `public/app.html` are in the installer.

**Tested:**
- Node.js syntax check of modified deployed script.
- Deterministic regression fixture extracts the live modal renderer; simulates React clearing `event.target` before processing queued state updates. Old version fails 12 field controls including *For Repair*; new version passes all 13 controls, with zero failures.

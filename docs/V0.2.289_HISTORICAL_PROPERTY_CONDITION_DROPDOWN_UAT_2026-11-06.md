## User request

The physical unit entry in **Property Accountability → Historical Property → Register historical property** showed an unconstrained **Condition or remarks** free-text input. The owner requested condition as a dropdown.

## Implementation

- Render the standard mandatory **Physical condition** dropdown separately for every historical property physical unit.
- Use the same canonical list as the existing Property Details correction editor: `Serviceable`, `Needs Maintenance`, `For Inspection`, `For Repair`, `Under Repair`.
- Blank or arbitrary free-text condition is rejected by the form and before `asset.opening` is submitted. Each unit's chosen value is passed unchanged to the existing `condition_note` field in the backend.
- Historical catalog quick-add preserves the selections when the user returns to the registration dialog. Serial number, room/location, legacy property number and existing acquisition details remain unchanged.
- The **Earlier IAR Receipts** physical-unit form remains unchanged, since this UI correction is specifically for historical registration.
- Formal **Unserviceable / For Disposal** remains in Property Condition & Disposal. No new disposal shortcut or electronic approval is introduced.
- No backend PHP changes, API changes, new permission grants, extra financial or stock posting, or SQL migrations. Existing auditing remains in place.

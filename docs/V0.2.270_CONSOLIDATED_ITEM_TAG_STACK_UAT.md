# IPDAMS v0.2.270 — consolidated item + property tag readability

Installed predecessor: v0.2.269. Source was taken from the v0.2.269 verified update ZIP; the Hostinger deployed `app.html` cache key and `DivisionConsolidation.php` source size matched that installation before this patch was made.

**Purpose:** In Division Consolidation → Current Asset Register, Asset Movements, Current ICS/PAR and ICS/PAR History, render the catalog **item description** on the first line and the original **property tag** on the second line in a single table column. This avoids adding columns and reduces horizontal scrolling in the existing reports. Rename the existing `Property Receipts` nav tab to **IAR Property Receipts**, because that view currently includes finalized IAR lines, not inter-office transfer receipts. Do not silently imply transfer receipts are absent from the actual custody history.

**Backend:** The `item` value comes from `item_catalog i JOIN assets a ON i.id=a.item_id`, within the existing protected office selection for current/historical ICS/PAR and asset movements. No special permissions, closure status or counts change.

**Property number decision:** Existing `PropertyRegistrationNumbers::reserve()` states existing property tags never change, and `PropertyTransferAcceptance` creates the receiving asset with the source property tag to maintain linkability. This release intentionally does not add re-tagging. If required by an authenticated policy, an optional *receiving-office reference* should be separately versioned/unique within that office, with original permanent property tag, source office, PTR/ITR number, receiving date, and full audit history retained. Do not change `assets.property_tag` or mutate old finalized documents.

**ICS/PAR History clarification:** One row is correct for the provided evidence: the original school ICS closed via PTR/ITR. The other two ICS rows are currently open (separate Division/school assets), and the other transfer events appear in Asset Movements, not necessarily as new finalized ICS/PAR documents. A prior internal custody event is **not** a new ICS/PAR unless a separate issuance document exists. This is a future reconciliation check, not an alteration made here.

## User request and implementation

Under **Property Accountability → Register & Review → Historical Property → + Register historical property**, an authorized school operator can click **+ Add missing catalog item** without losing their unfinished acquisition and physical-unit fields. A separate floating form creates a **PPE** or **SEMI_EXPENDABLE** item with name, existing unit and eligible **Division-approved class / UACS**. On success, the historical registration form resumes with the new item selected; no user navigation to Reference Data required. A duplicate visible name/category/unit is selected without a redundant POST.

The existing `master.item.create` endpoint is used. It authenticates, scopes the requesting office, checks permission, active Division-approved classification and UACS account, uniqueness and writes the catalog and its UACS mapping transactionally with audit. **No new PHP route, permission grant, migration, financial posting, stock movement or property registration** is introduced. A quick-added school catalog entry stays scoped to its school (visible also to its supervising Division according to existing sharing rules). Division-origin entries retain Division catalog scope. **Super Admin Office Viewer remains read-only.** If unit or approved classification is missing, the UI instructs the user to configure it through the existing authorized Reference Data workflow.

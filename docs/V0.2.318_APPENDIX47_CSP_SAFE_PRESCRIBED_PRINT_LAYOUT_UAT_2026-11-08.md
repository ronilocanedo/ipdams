## Observed failure and corrective approach

The owner's v0.2.317 screenshot shows default browser formatting: oversized left-aligned title, stacked header, and left-side employee/SDS signers. The existing print HTML embedded a <style> element inside a newly opened about:blank window. An inherited Content Security Policy that blocks inline styles is a likely mechanism, not confirmed by live server-header inspection.

The new certificate uses **same-origin external versioned print CSS**, verifies the linked stylesheet is loaded before printing, waits for popup load and fonts, and fails visibly if CSS is unavailable. The CSS follows the user's sample with one-page A4 proportions, upper-right Appendix 47, centered small title, two-column Entity/Fund and SDS/Station, slash-mark travel conditions, selected evidence on separate lines, and employee/SDS signatures on the right.

No non-prescribed audit warnings are printed, and all claim data, stored evidence selections, approval checks, signed-paper requirement, financial logic and access controls remain unchanged.

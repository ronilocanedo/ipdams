# IPDAMS v0.2.271 — ISBN directory audit and textbook safety gate

**Predecessor:** v0.2.270. **Target:** v0.2.271. **Date:** 2026-11-04.

## Scope delivered

- The current Textbooks page has a **Book Directory** with search and page controls, shared bibliographic data from the existing global `textbook_titles` table. Each valid ISBN-10 is normalized to its ISBN-13 equivalent; matching legacy rows are grouped without editing source IDs. ISBNs with invalid checksums, blank ISBNs, and conflicts between title/grade/subject metadata are flagged for review. An entry with no ISBN is not automatically discarded; the future controlled registration workflow will require an official LR identifier.
- The existing **My Office Textbook Stock** and **Original Movement History** remain visible and scoped through their existing API routes.
- The previously generic `textbook.opening` and `textbook.move` POST endpoints return HTTP 409 *before any posting or idempotency-key write*. This intentionally pauses all unmanaged textbook receipts, distributions, transfers, lost/disposal adjustments and count corrections while formal receipt, approval, dispatch and acceptance transactions are developed. The advanced UI selector no longer offers those unsafe actions.
- Any open school or Division user with an authorized active school/Division workspace may search the global **bibliographic** directory; no school-specific stock, employee or learner details are disclosed by the directory.
- Directory scans at most the **first 3,000 original title rows** per request to bound resource use on shared hosting; a conspicuous incomplete-coverage warning is shown if the table exceeds that limit. This is an audit preview, **not** a claim of universal ISBN uniqueness at the database level.
- No changes to existing `textbook_titles`, `textbook_batches`, `textbook_movements`, property assets, procurement, financial data, or schema. No migrations. Existing original records remain immutable and traceable.

## Why this gate precedes physical textbook distribution

The original `Domain::textbookOpening()` creates a fresh title for every batch, even when an ISBN already exists. `Domain::textbookMove()` posts `LOST`, `DISPOSAL`, `TRANSFER`, `RECEIPT` and count adjustments immediately from a generic form without receiving school confirmation or competent authorization. Enabling transfers on those routes would risk double counting and unaudited write-offs. Stage B must first introduce receipt documents and a canonical DB-unique title registry after the existing live title table's duplicates have been audited. No title IDs will be merged without approved mapping and independent backups.

3. Search a known valid ISBN-13 and its equivalent ISBN-10. Each should find the same edition group. Search by title and subject; inspect missing, invalid or conflicting ISBN flags. Do not edit or merge old titles yet.

6. If the directory displays **catalog coverage incomplete**, pause reconciliation until the auditor implements server-side cursor paging for a larger title population.
7. Report actual title counts and any ISBN conflicts found. We will use these to design a non-destructive migration mapping for the unique ISBN registry before new receipts.

# IPDAMS v0.2.290 — Historical Property Register and Current Asset Ownership Reporting

**Prepared:** 2026-11-06 (Asia/Manila).  
**Status:** version-gated installer locally validated; owner installation/live authenticated acceptance pending.

## Owner reports

1. Registering a historical property is successful and adds the asset to Asset Register, but **Historical Property** subtab stays visually blank.
2. Property transferred to the Division and acknowledged by the receiving Division is still appearing in the sending **school's current reports**.

## Root cause

- Historical Property previously rendered only an introduction and **Register Historical Property** modal, not a list of registered records.
- The existing accepted cross-office transfer engine correctly sets original sending-school `assets.status='TRANSFERRED'` and creates an `ACTIVE` receiving-office asset with lineage, but several school current-asset datasets selected all rows solely by `assets.organization_id` without excluding transferred-out status.
- The Division Consolidation current-asset query was already scoped to `a.status='ACTIVE'`; no change to it was required.

## Implemented scope

- Historical Property now displays its own **paged 25-row register** based on the existing scoped `list(kind=assets,register_page=1,source=HISTORICAL_OPENING)` endpoint. It shows property number, item, serial number, date/cost, location, status and **View Details**, refreshes after registration, and offers a clearly separate **Show transferred-out history** mode.
- Default Asset Register status **All except transferred out** excludes `a.status='TRANSFERRED'` at SQL level; explicitly selecting **Transferred out (history)** returns historical records. Normal `list(kind=assets)` and role-function special ASSET live register also exclude accepted transferred-out source records.
- Semi-expendable report `$assets` dataset for **Annex A.1 (property card)** and **Annex A.8 (physical-count preparation)** excludes completed transferred-out source assets; report caption explains that **Annex A.4/A.5 movements and Annex A.7 past issuance** remain audit evidence, not current asset balances.
- No replacement of `PropertyTransferAcceptance` transaction, asset organization IDs, historical ICS/PAR, audit events, receiving office asset rows or document numbering. No stock/financial posting, migration, reset or permissions change.

## Owner UAT

1. Retain separate website and SQL backups. Stage **only** the ZIP matching v0.2.289 or v0.2.288, verify six files and zero migrations. Do not bypass predecessor mismatch.
2. Browser hard refresh. Open School Property Accountability → Historical Property: previously saved historical units should now appear. Check View Details and Refresh. Do **not** create another fictional property to test visibility.
3. Go to school **Asset Register**, default **All except transferred out**: an accepted transferred-to-Division asset should not be counted as current. Filter **Status → Transferred out (history)** to view the original sending-school record.
4. Compare the receiving Division's current asset register; its received copy must be present once, with correct source lineage and condition.
5. In the school's semi-expendable **Annex A.1/A.8**, transferred-out items must not appear in the current asset/physical count preparation dataset. **Annex A.4/A.5 and historical ICS/PAR** should still show genuine past transactions.
6. Compare real totals and forms to your known property transfers. If mismatched, do not delete/edit records directly; report document number and receiving office for an audited follow-up.

**Meaning of current**: latest accepted transfer ownership. This is **not** a retrospective, as-of-any-past-date stock balance model; past issuance/transfer histories intentionally retain events that happened before the ownership change.

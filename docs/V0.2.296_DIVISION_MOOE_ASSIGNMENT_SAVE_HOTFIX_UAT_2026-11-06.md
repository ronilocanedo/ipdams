## Confirmed root cause

The v0.2.295 backend `Domain::saveDivisionMooeAssignment` accepted the posted request as `$d`, but the transaction closure used `function()use($division,$school,$employee,$effective,$expected)` **without capturing `$d`**. Within the callback, `($d['historical_appointment_attested']??false)===true` consequently always failed for backdated assignments, even with the checkbox checked, and the official memorandum reference could not be read. This produced the exact error reported by the owner, *“Confirm that the earlier MOOE assignment is supported by an official Division document.”*

A second backend defect used `$staff['id']` for the stored employment-episode link although `staffActive()` returns that column as `$staff['assignment_id']`. Both are corrected. No database row is retroactively altered; a properly saved version carries a correct employee assignment ID.

The frontend also retained the prior red error even after the historical-evidence checkbox was selected. This hotfix clears the old message on checkbox/reference/date/employee change, labels the paper-document requirement visibly, enforces 15–300 characters for the reference in both client and existing server validation, and corrects checkbox layout. The server remains authoritative for Division/school scope, active employment, nonfuture effective date, increasing versions, actual documentary evidence and append-only audit.

**No employee effective/hire date rewrite, simulated paper approval, RIS/ICS mutation, financial posting, stock movement, SQL migration or role permission expansion.** The assignment is an administrative transcription of genuine Division documents, not an electronic signature.

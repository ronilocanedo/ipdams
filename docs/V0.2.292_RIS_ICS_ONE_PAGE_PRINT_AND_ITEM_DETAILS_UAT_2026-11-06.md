## Implementation

- **Print RIS + ICS** from a finalized ICS now uses **one A4 portrait page for 1, 2, 3, or 4 ordinary-sized property items**. Both formal Appendix 63 RIS and Appendix 59 ICS remain separate sections with their own full bordered item tables and physically signed signature sections. The RIS 'NOTHING FOLLOWS' line remains.
- For **5+ items**, exceptionally long item descriptors, or unusually long signatory names, the printer falls back to **separate A4 sheets / continuation pages**, avoiding truncated forms. No forced scaling that would make wet-signatures unreadable.
- In **RIS and ICS Description cells** the main item name remains full-size; available **Brand, Model, Serial No.** appear below in smaller **italic** print. Read directly from authenticated `property.registration.detail`: `details.shared.brand`, `details.shared.model`, and physical unit `details.serial_number` (fallback `unit.serial_number`). Each item gets **its own serial number**, not one serial replicated to the entire batch. Absent optional values are omitted and all values are HTML-escaped.
- Standalone authenticated **Print ICS** (PHP backend) uses the same subtext using saved `assets.property_profile.shared` and `assets.serial_number`. Generic supplies RIS does not fabricate equipment brand or serial. No signature identities, authority dates, fund clusters, RIS numbers, costs, or transactions are invented.
- CSP-friendly external print CSS remains; no React.Fragment, accounting mutation, asset editing, or role changes.
- **Files:** `app/OfficialAccountabilityPrint.php`, `public/api/print.php`, `public/assets/app.js`, `public/assets/ics-ris-pair-print.js`, `public/assets/ics-ris-pair-print.css`, `public/app.html`.
